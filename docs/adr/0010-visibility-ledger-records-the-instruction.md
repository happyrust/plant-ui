# 可见性台账另记一份，记的是指令而不是渲染结果

模型树要在行内摆一枚能反映当前可见性的眼睛图标，于是绘制层第一次需要**读**可见性。
在此之前它只往外发 `ModelAction::SetVisible`，从不关心结果。查下来宿主手上没有一份
能直接回答这个问题的数据，所以新增一份**可见性台账**：按参考号记住最后一次显示 /
隐藏指令的方向，容器行照它画，不去推子树。

现有的两份数据都答不上来：

- `RefnoMeshEntMgr.map`（`editor_ui/shared.rs:113`）+ 实体上的 `Visibility` 组件，是真实
  渲染状态，但只覆盖**几何行**。SITE / ZONE / PIPE 这些容器行自己没有 mesh 实体，
  `ShowModelEvent { deep: true }` 收到一个 ZONE 之后是一路展开到实例层才落到实体上的，
  容器本身从头到尾没进过那张表。
- `HaveShownRefnos`（`model_system.rs:196`）看着像，其实不是。`model_system.rs:591-594`
  里**无论显示还是隐藏**都先 `shown_refnos.insert(...)`，下一行才取 `let hide = !event.visible`；
  而且全工程没有任何一处从它里面移除过元素。它记的是「曾经被提到过」，只增不减。

把这两份凑一凑也不行：容器行的真实子树状态**推不出来**。折叠的子树压根不在 `E3dTree` 里
（只有展开过的节点进 `NodeIdRefnoMap`），要推就得查库；部分加载的子树推出来的结论还是假的。

台账因此**挂在 `ShowModelEvent` 的消费端**（`fetch_e3d_insts_system`），不挂在
`plant_ui_host.rs` 的命令派发里。SSC、房间、版本对比、手动增量更新至少五处也在发这条事件，
只拦 UI 那一条的话台账很快就和现实对不上。

## Considered Options

- **从后代实体推容器行的三态（全显示 / 全隐藏 / 部分）**：信息最准，也是别的建模软件的常规做法。
  但要么对折叠的子树查库，要么承认「没加载的后代不算」——后者算出来的「全显示」在用户眼里
  就是错的。
- **容器行不画眼睛，只有几何行画**：一行假话不说，实现也最省。否掉是因为用户最想点的恰恰是
  ZONE 那一行，叶子一个个点过去不现实。
- **绘制层自己记一份被隐藏的 refno 集合**：最便宜，不用动宿主。但 `plant-ui/src/lib.rs:1-2`
  写死了「不认识数据库、不认识 Bevy：输入 &Vm，输出 Vec<Cmd>」，而且视口工具栏、`S`/`H`
  快捷键、`HideAll` 都能改可见性，树上不知道，图标立刻开始说谎。

## Consequences

- **「未加载」是第三个真状态，不是设计上的花样。** 开机时台账是空的，整棵树每一行都既不是显示
  也不是隐藏。二态的眼睛在这里必然说谎，所以 `TreeRowVm` 上那个字段是三值而不是 `bool`。
- **台账说的是指令，不是画面。** 用户显示一个 ZONE，其中若干后代因为没生成模型而始终没出现
  （ADR-0009 说的那件事），台账照样记「显示」。这是有意的：眼睛回答的是「我让它显示了吗」，
  「它到底出来没有」是模型补齐那条链路的事，两者别混。
- **台账要有移除路径，`HaveShownRefnos` 的教训别再犯一遍。** `HideAll` 之后台账里所有条目都得
  翻成隐藏；元素被增量更新删掉之后条目要清掉。只增不减的集合两年后就是一份没人敢信的数据。
- **重建行表的时机要跟着台账变。** `plant_ui_host.rs:506` 现在只在 `tree_dirty` /
  `expanding.is_changed()` / `Loading` 三种情况下重新展平。台账变了也得重来，否则点完眼睛
  要等下一次展开才刷新。而 `ShowModelEvent` 是异步落地的，得按台账自己的变更信号来判，
  不能指望当帧。
- **`HideAll` 的窟窿更明显了。** 计划文档 §6.2 已经记着「有 `HideAll` 没有 `ShowAll`」。
  眼睛做出来之后，用户会看到满树的斜杠眼却没有一键恢复的地方。补 `ModelAction::ShowAll`
  之前要先确认 `HideAllPdmsMeshEvent` 有没有对偶的恢复事件。
