# 落定重载只换变了的单元或库，不再整场重装

状态：**已接受**（2026-11-12 20:01 plannotator 评审批准，无批注。起草：2026-11-12 grill-with-docs；第一轮用户「全部按推荐」，Q6 定 (a)；
第二轮 Q14 把两条边界——元件库变了、设计库会话没变；只登录不改几何——按推荐写进后果 2 / 3）。
取代：ADR-0021 中「上屏后若又有新保存落库，仍走既有的『自动刷新只换树 + 日志提示再点取回工作』」那一句；ADR-0021 其余
（取回工作 = 点击即清场、只重装已加载集）不变。
计划：`docs/plans/model-load-speed-parity.md`（T7）。术语：`CONTEXT.md`「落定重载」「取回工作」。

## 背景

「后台模型落定之后三维怎么跟」这件事眼下有三处说法，互相对不上：

- **代码。** `crates/plant-ui-app/src/main.rs` 的 `auto_refresh`（约 2419–2437 行）在后台模型落定（模型屏障就绪）后走
  `FullReload`，注释写「也用于自动保存变化」。项目里任何一个 DESI / ISOD 库的 `file_latest_sesno` 变了
  （`source_versions.rs::observe`）、或有批次应用、或有单元落定，就把已加载范围整场重查重装（`main.rs` 约 4373–4429 行）
  ——不管变的那个库有没有加载进场景。
- **ADR-0021 的文字。** 上屏后若又有新保存落库，只换树，日志提示再点取回工作。
- **`docs/plans/get-work-clear-and-reload.md` 第 30 行。** 这条欠账重载只服务「查询失败」。

代价是实打实的：按现在的取法，8 万件的 SITE 重查一遍记录约 20 秒；网页端整库重装要十几分钟
（`docs/evidence/2026-10-22-e3d-look.md` 10-25 实测）；重装期间场景空白。而触发它太容易——E3D 每登录一次会话号就涨
（plant3d-web ADR 0072），只登录、不改几何也会触发一次整场重装。

## 决定

### D1　范围 = 落定的交付单元，退而求其次是变了的库

有 `fresh` 单元清单时，沿用 `AutoRefresh::Units` 那条路，精确到落定的交付单元。没有单元清单
（读穿模式的保存没有队列任务，只有 `SourceVersions` 看到会话号变了）时，退到「变了的库」名下的已显示范围。
别的库变了，一个 `model/records` 都不发。

### D2　换法 = 按目标卸旧装新

走右键「重新生成模型」已在用的 `View3d::refresh`：对要换的范围卸旧装新，不清场。相机与显示方向不动，眼睛按实际结果（ADR-0016）。

### D3　取回工作不变

取回工作仍是手动的清场重装（ADR-0021）。落定重载不是取回工作，不改它的语义，也不替它。

### D4　账怎么记

`source_versions.observe` 改为报出变了的库集合（今天只是一个 bool）；装载时按回执（`ModelRecords.sources` 已按库分桶）
记下每个范围涉及的库。

## 为什么不是别的做法

- **(b) 回到 ADR-0021 的文字，新保存只换树、日志提示再点取回工作。** 退功能：用户已经习惯「存完自动跟上」。
- **(c) 照 plant3d-web（ADR 0072），只在树行标「有更新」由人点。** 多一个人工动作；两端行为虽然一致，但不是用户要的。

## 后果

1. 要维护一本「范围 → 库 / 单元」的账。
2. 元件库（CATA）变了、设计库会话没变：源版本判据（`source_versions`）本来就不看 CATA；后端批次落定给出单元清单（`fresh`）
   就按单元重载，否则不动，追新靠右键「重新生成模型」（Q14 (1)，按推荐，评审已确认）。
3. E3D 只登录不改几何也会让会话号涨（plant3d-web ADR 0072）：按现在的判据会当成「有新保存」，触发的只是这个库名下范围的重载
   （一个库最多几秒）。第一版接受，不做「会话里有没有几何改动」的判断——那要后端配合（Q14 (2)，按推荐，评审已确认）。
4. 自动重载期间不再整场空白，相机不跳。

## 实施约束

1. 测试：先装 7333 库的范围，再让 7999 库保存一次——后端 `model/records` 请求 = 0、场景不动；7333 库保存一次——只有 7333 名下的范围重载。
2. `source_versions` 现有三条测试改成集合语义，并加两条。
3. `CONTEXT.md` 新增「落定重载」，「取回工作」词条补一句。
4. 设置项「落定后自动重载」（`plant_ui::settings::Settings` 加一格 bool，缺省开，随 `settings.ron` 按机器落盘）：关 = ADR-0021
   原文字的「只换树 + 日志提示再点取回工作」。它是这条决定的回退口（计划第九节），不是第三种重载方式。
