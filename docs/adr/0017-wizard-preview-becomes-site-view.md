# 向导预览重构为 SITE 视图，勾选决定执行子集

> **状态：设计与文档已定案（2026-08-07 拷问，六题全部人工答复，无超时自决；
> 同日画板验收两轮反馈已吸收——CATA 完全不展示、Q2 改判 SITE 平铺）。**
> 画板 S2-G / S2-H 待最终验收；验收通过后才动代码。契约侧对应 gen-model ADR-020。

「我对着的是 SITE，不是文件」——设计人员在模型树上认的是 SITE 名，手动更新向导却让他
对着 `ams-8009.desi · db8000` 这样的文件行做决定。这次把预览树重构成 SITE 视图，并在
行前加勾选框，让人**选择这次要更新哪些**。

## 架构事实（不因界面改而改）

三条全部出自 ADR-0015 的查证，这里只引不证：

1. **数据应用切不到 SITE。** 最小执行单位是（dbnum, 会话号区间），会话是库级写入记录，
   水位是库级单调值。SITE 只能当选取入口，不能当执行范围。
2. **SITE → dbnum 映射干净。** 所有权链不跨库，一个 SITE 属于且只属于一个库。
3. **执行子集需要 execute 加 `dbnums` 过滤**——ADR-0015 后果第 1 条设计过、没实现，
   这次由 gen-model ADR-020 兑现。

## 六题定案（2026-08-07）

| # | 题 | 定案 |
|---|---|---|
| Q1 | 勾选语义 | **同库联动**：勾任何一个 SITE = 勾中整库，同库兄弟 SITE 一起亮，行上说明原因。勾选状态与实际执行范围一一对应，不存在半选态 |
| Q2 | 树层级 | ~~库分组头 → SITE 子行 → 交付单元~~ **画板验收时改判（2026-08-07）：SITE 平铺顶层**——「用户不需要看文件，用户希望看到的是 SITE 节点」。SITE 行（勾选框 + 名称 + 增删改计数）直接是顶层；库级事实（两个时间 · sesno 区间 · 同库联动名单）迁进 SITE 展开的**详情行**，同库多 SITE 时按 SITE 重复画（明确接受的代价）；同库联动用 SITE 名单表达（「与 /1WCC-EQUI 同库联动」），dbnum 不上预览树。默认只列有变化的 SITE 不变 |
| Q3 | 两个时间 | **都用 E3D 会话时间戳**（同一把尺子，相减 = 文件里还有多大时间跨度的改动没被吸收）。新契约字段 `applied_sesno_time` / `file_latest_sesno_time`，从未应用时为空 → 「从未应用」。逐会话的 `sessions[].date` 只记为后续候选 |
| Q4 | 文件级状态 | **同一棵树分三段**：可执行（SITE 子行）/ 需初始化（库行可勾，标「首次导入 · 整库生成」，无 SITE 子行——从未解析，PE 里没有它的数据）/ 本期不执行（阻断 + 够不着，不可勾）。默认全勾，与现状「开始更新 = 全部批次」等价 |
| Q5 | 契约清单 | `DbnumPreview.sites[]` + 两个时间戳 + execute `dbnums` 子集过滤（过 `in_scope`）。优先根排序不做（依赖 G5/G6 未验收地基）。**预览请求不变，预览永远全范围扫描**，勾选只影响 execute |
| Q6 | 交付边界 | 设计 + 文档本次完成；画板验收后再开实现 |

## 两处明文推翻

- **ADR-0011「分组一律按 dbnum」在向导预览树上整条推翻**（2026-08-07 画板验收升级：
  最初只收窄为「顶层按 dbnum、SITE 作二级」，验收时进一步改判 SITE 平铺——预览树上
  **不再出现任何 dbnum / 文件分组**）。当年退役 ZONE 分桶的理由是产品里不该并存两种
  分组惯例；这次的回答是：向导对**人**说 SITE 的语言，dbnum 只在确认页批次行的括号里
  与任务队列对账时露面——两种口径各守一处，不在同一张视图里打架。任务队列（S12）
  仍按 dbnum 分组不变。
- **ADR-0015 Q7「向导里不加收窄入口」作废。** 向导现在就是子集选择的主入口。
  ADR-0015 其余结论（右键优先更新、排期在 P0-A + P1 之后、worklist 优先根）不动。

## Considered Options

- **勾选语义**：同库联动（采纳）vs 自由勾选 + 「将随库一并应用」标注。后者视觉上像
  部分选择、实际什么都没少做，靠文案自救——违背「按钮文案不许含糊」的仓规。
- **树层级**：库分组头下嵌 SITE vs SITE 平铺顶层。拷问时采纳前者（库级事实只画一遍、
  tri-state 联动自然），**画板验收时用户改判后者**——「不需要看文件」压过信息重复的
  顾虑；重复的库级事实收进 SITE 详情行，「勾一个亮同库」由详情行里的联动名单解释。
- **排除行**：非 DESI（CATA 等）**完全不展示**（采纳，2026-08-07 验收反馈收窄）：
  不占树行，范围行也不再交代排除计数，确认页的「不会执行 · 排除」行一并删除。
  此前中间方案是「树行删、范围行留一句排除计数」——验收时被明确否掉；树行不出
  这半边与 S2-E 一直写着的「排除不出行」注记终于一致。契约不变（排除信息照旧
  在响应里），只是 SITE 视图不画。

## Consequences

- **画板**：新增 **S2-G（预览 · SITE 视图）**、**S2-H（确认执行 · SITE 视图）**，
  S2 / S2-B 退为历史参照。S2-G 树 = SITE 平铺 + 详情行 + 三段式（可执行 / 首次导入 /
  本期不执行）；首次导入与阻断行保持文件级身份——没有 SITE 可说的行才许露文件名。
  S2-H 相对 S2-B 改五处（含删一行）：会执行批次行**以同库 SITE 名单为题**、dbnum 收进
  「同库一批（db8000）」括号（与任务队列对账的唯一露面处）、不会执行卡新增
  「**未勾选 · 本次跳过，水位不变**」行（标题同用 SITE 名，与阻断/够不着三类不许合并）、
  「不会执行 · 排除」行**删除**（非 DESI 完全不展示，计数不含它）、
  重扫提示限定「对勾选范围重新扫描；未勾选的不扫描、不入队」。
- **组件**：`C/TreeRow` 加了一个默认隐藏的 `Check` 节点（勾选框），既有实例不受影响。
- **验收基准**：`design/MODEL-UPDATE-FIELD-MAP.md` 新增 §2-G 与 §3 追记，每个新元素
  都标了字段出处；待新增字段全部指向 gen-model ADR-020。
- **契约依赖**：gen-model ADR-020 的三项新增（`sites[]`、两个时间戳、execute `dbnums`）。
  界面实现不得先于契约落地。
- **实现清单（画板验收后）**：
  1. gen-model：ADR-020 三项 + specs 两份同步更新；
  2. plant-ui：`model_update.rs` 预览树重构为三段式 SITE 树 + 勾选集状态；
     `model_update_api.rs` 的 execute 带 `dbnums`；
  3. 跨库级联单元挂触发批次的分组下，行上标注来源库。
