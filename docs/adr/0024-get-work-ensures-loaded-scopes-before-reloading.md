# 取回工作的三维先经模型服务补齐到文件最新，再重装

ADR-0021 把取回工作的三维半边定成「点击即清场、只重装已加载集」，重装走的是
`plant_ui_data::model_instances`——只读 SurrealDB 里**已经生成**的实例。这在旧形态下成立：
数据批次 worker 在人点取回工作之前就把模型重算好了。gen-model 切到 direct 形态之后
（gen-model ADR-053 / ADR-054：树与模型按需从库文件读，不起 watcher / worker，模型只在
`ensure` 时按文件最新会话生成），这条前提没了：设计人员 SAVEWORK 之后，树已经是文件最新，
点取回工作重装出来的三维却还是**上一次生成**的几何——画面在冒充新数据，而且没有任何东西
会替它认这件事。

取回工作的三维半边改为「清场 → 先对清场前点过眼睛的范围目标逐个 `ensure` → 再重查快照
里的模型」：

- `ensure` 走的就是 eye 那条路（ADR-0009，`POST /api/v1/model/ensure`，`force = false`）：
  凭证「当前」（`gen_root.source_end_sesno >= 文件最新`，gen-model ADR-054 单调判据）的生成根
  服务端直接算命中，只有被改到的根真重算。取回工作对三维的语义从此与点一次眼睛完全一样，
  只是范围是「清场前场景里的那批」。
- 范围目标是**树节点**（`Evt::ModelScope` 回包非空时登记的 `scope_targets`），不是逐个模型
  refno：一个目标下服务端一次归并全部生成根；快照可上千模型，逐个打 ensure 是上千次 HTTP。
- 快照多记一份目标名单，「只记第一次、成功落地才消费」不变（ADR-0021）；重试与欠账补载
  按同一份名单先 ensure 再重查。名单只按 refno 排序去重，不按树序——ensure 对同一片范围
  幂等，先做 ZONE 还是先做它底下的 BRAN 总工作量一样。
- ensure 失败**不阻断**随后的重查：空场景比旧几何更坏。但失败要出声：逐目标一条日志
  带 code 与出路（超时 → 服务端可能仍在后台生成，完成后再点一次；409 → 该库正被占用；
  其余 → 其下模型可能仍是旧几何），落地那句「三维模型已就绪」后面挂一句
  `核对 N 个范围 → 重算 g 个生成根、命中 c 个；k 个范围核对失败`。
- 没有范围目标可核对的快照（旧路径加载的模型）按上次产物重装，日志说出来。
- 重查范围、显示 / 隐藏回放、相机不动、新增元素只进树、库里删掉的自然消失——ADR-0021 的
  五条一个字不改。

**「不应用任何数据」这句在 CONTEXT.md 里精确成：不推进 `applied_sesno`。** `ensure` 只写
模型面自己的状态（`gen_root` 凭证、`inst_relate` 产物），不碰数据水位、不跑数据批次；
gen-model ADR-056 N5 承认「两枚凭证」（数据水位 / 模型凭证）各走各的，取回工作把模型那一枚
追到文件最新，正是这条口径。

代价是切换期的：gen-model P2-2「凭证前移」落地前，SAVEWORK 之后第一次取回工作等于范围内
全部根重算（gen-model 审核 S8、ADR-054 明写的一次性代价）；一个整 SITE 的范围可能撞服务端
120 秒上限，回 504「后台继续跑」，再点一次即拿到结果。日志把这两件事都说出来。
