# 执行进度归任务队列视图，向导只留预览与确认

模型更新任务窗现在是三步向导（更新预览 / 确认执行 / 执行进度），八张画板都照它画完了，
`model_update.rs` 3202 行也都落在这个形状上。服务端把手动与自动合流成一条数据批次队列
之后（gen-model ADR-011），**第三步站不住了**：同一个 dbnum 的进度会有两个画面，
而向导那个只看得见「本次运行」——人点完「开始更新」，如果前面还排着两个库，S4 会显示
一个不动的界面，而它说不出自己为什么不动。

所以：**向导只留预览与确认两步，执行进度整体迁到一个常驻的任务队列视图**，第二步按下
之后跳转过去。留下的两步恰好是向导真正不可替代的部分——S2-B 存在的唯一理由本来就是
「按下去的是一个不可取消的按钮」，那道关不能没有，也不该由一条持续滚动的队列来承担。

队列视图进 dock，与命令行 / 日志并排。监控与向导的性质不同：向导是人主动发起、用完就关，
队列是一直在跑、你希望余光能扫到。「方便看到某个 dbnum 目前的进展」这句话里的「方便」
两个字，基本上把「得先点开一个浮窗」排除了。

## Considered Options

- **向导一行不改，队列监控另开一个窗**：已有实现零浪费，上得最快。但同一个 dbnum 两个
  画面，且向导的 S4 会在排队时展示一个解释不了自己为什么不动的界面。
- **队列为主，向导降为队列上的一个「深度预览」动作**：信息架构最干净，也最适合自动同步
  常开的场景。但重写量最大，而那道不可撤销的确认关要重新找地方放。
- **砍掉向导**：界面最少。但执行前看清变化量与阻断情况的能力也一起没了，而那正是八张
  画板花最多力气的地方。
- **只在状态栏摆摘要，点开向上展开一块浮层**：不占任何常驻布局。但 26px 里已经有四样
  东西，而浮层也装不下逐 dbnum 的两阶段明细。

## Consequences

- **S4 / S4-B / S4-C 三张画板的内容迁到队列视图上重画。** 断线降级的形态照搬 ADR-0005 与
  ADR-0007 的结论：进度条走轮询、断线不影响其准确性，要降级的是列表区，不是那条条。
- **状态栏只加一个计数**，负责在队列视图被折起时依然叫得住人。它不重复面板上的明细
  ——同一组数字两处渲染就是两处维护。
- **ZONE 分桶全局退役。** S2 预览结果从 dbnum → ZONE → 交付单元三层改为 dbnum → 交付单元
  两层；`DbnumPreview.zones[]` 退回 `MODEL-UPDATE-FIELD-MAP.md` 第 8 节「契约里有、界面
  还没用的字段」那张表。`CONTEXT.md` 的「ZONE 分桶」与「归属未知」两条术语已删。
  分组一律按 dbnum——那恰好是执行边界与队列键，产品里不该并存两种分组惯例。
- **词表「运行」退役**，`Run` / `RunVm` 两个类型要跟着改口径：一行现在代表一个数据批次，
  不再代表一次手动更新的执行实例。
- **房间重算是一条与 dbnum 列表平级的跨库泳道**，不挂在任何 dbnum 行下。ADR-010 §7 把
  房间任务的行 id 刻意做成不带 dbnum，那个 `dbnum` 字段是「最后一次触发来源」而非归属，
  拿它分组会误导。泳道上的数字来自 `kind = room_recalc` 的任务记录（gen-model ADR-011
  第 10 条）：待重算面板数与构件数随任务详情带出，「已等待 N 分钟」是本地量，
  从上一轮的 `finished_at` 起算。
- **S2-D 少一种形态。** 「已有任务在跑 · 409 · conflict」不再是错误——执行请求一律入队，
  那一格改成入队回执「已入队，排在第 N 位」。`MODEL-UPDATE-FIELD-MAP.md` 第 6 节要跟着改。
- **预览可能报大。** 单飞预检删掉之后预览与数据批次可以并发，正在被应用的会话会被算进
  「待应用」。预览结果上要标注「N 个库正在应用，数字可能偏大」——本仓不允许一个说不清
  来路的数字，那就把它说清楚。那个 N 由队列快照本地算得出，不需要新字段。
- **队列面板要另开一格「本期不执行」。** 阻断与排除的库不入队，队列里没有它们的行；
  而阻断是「这个库水位为什么一直不动」的唯一解释，面板里没有它，人只会以为它没变化。
  为此 `GET /dbnums` 要补 `anomaly` / `blocked`（gen-model ADR-011「结果 / 约束」）。
  文案与 S2-E 那七种形态保持一致，两处不许各说各话。
- **行内明细默认折叠，只有「运行中」那一行默认展开。** 与变化树已有的口径一致
  （会跑的库默认摊开、不跑的收起）；队列是常驻视图，全部展开会把命令行与日志挤没。
- **只画当前项目，不混排。** 一个 gen-model 进程只服务一个项目（`DbOption.project_name`），
  跨项目要先有多项目路由。快照里 `project` 与当前项目不一致的条目**直接不显示**，
  不许当成本项目的活画上去。
- 逐项字段出处见 `design/QUEUE-FIELD-MAP.md`，那张表是实现的验收基准。
- **同一个 dbnum 最多同时占两行**（一行运行中、一行排队中），这是服务端「排队中合并、
  运行中冻结」的直接后果，界面要把这件事说清楚，不能让人以为是重复项。
