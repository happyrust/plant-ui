# 界面语言改说「保存」与时刻，sesno 退回内部

> **状态：设计层已定案并人工验收放行（2026-08-10 拷问，九题全部人工答复，无超时自决）。**
> 画板（验收基准板）、两份字段映射与 CONTEXT.md 已按本 ADR 改毕，并逐板对照复核过一遍；
> 三条开放项见文末，其中两条是**旧板就有的口径含糊**，验收时确认原样留着、不在本轮顺手决定。
> gen-model 契约 / 存储迁移与 plant-ui 代码可以开始推进。
> 契约侧新增字段以本 ADR 为出处（gen-model 侧后续应有对应 ADR 落地）。

「设计人员记得住自己周二下午存了什么，记不住 42 号」——手动增量更新的整条功能流
（向导窗 → 任务队列 → 状态栏）此前用 sesno 区间作对账语言。这次把界面语言整体换成
**保存的写入时刻**，并把「会话」这个词从界面上退役：一次 E3D 存盘 = 一条会话记录，
对人说话时它就叫**一次保存**。

## 架构事实（不因界面改而改）

1. **同一把尺子（ADR-020）**：所有对人露出的时刻都是 **E3D 会话写入时刻**
   （`session_time_rfc3339` 从会话页现读，RFC3339），本地显示 `MM-DD HH:MM`
   （`model_update.rs::e3d_time`）。挂钟时刻（`applied_at`）与它不是一把尺子，不得混用。
2. **执行边界仍是（dbnum, 会话号区间）**：水位、回退检测、区间起点、冻结判定全部
   继续用内部序号 sesno。时刻只是**显示代理**，不参与任何判定。
3. **回退后已应用会话页不存在**：文件被换回旧版本后，`applied_sesno` 的会话页在
   当前文件里读不到，其写入时刻**不可现读**；水位表此前只存 `applied_at`（挂钟）。
   这是回退卡时间化必须补存储的根本原因（见 Q6）。
4. **逐会话时刻几乎免费**（gen-model ADR-020 明言）：扫描本来就在解析会话页，
   补逐条时刻不需要新的 IO 通道，只需要进契约。

## 九题定案（2026-08-10）

| # | 题 | 定案 |
|---|---|---|
| Q1 | 去 sesno 的范围 | **整条功能流**：向导窗 + 任务队列视图 + 日志文案 + 画板状态栏示例。同一功能流不出现两种对账语言 |
| Q2 | 替代语言 | **时间对 + 次数**：`07-30 18:24 → 08-07 14:10 · 8 次保存待应用`。保留区间感（两端相减 = 积压了多久）；次数照报（它是数量，不是 sesno） |
| Q3 | 区间左端点 | **窗口自身两端**：第一条待应用保存的时刻 → 最后一条的时刻。是对 `start_sesno → end_sesno` 的诚实翻译；SITE 详情行的「上次应用 → 文件最新」语义保持（右端一致，左端各有标签，不矛盾） |
| Q4 | 「会话」→「保存」 | **界面文案 + 画板 + 字段映射 + 术语表全改**。「保存」立为界面语言（N 次保存、保存于…），「会话 / sesno」降为仅限内部（代码、契约、日志）。「命令会话」是命令行视图的另一概念，不受影响；代码标识符与 gen-model 契约字段名不动 |
| Q5 | 并入保存的逐条列出 | **逐条列保存时刻**：`预览后并入 3 次保存（08-07 14:21 / 14:27 / 14:33）`。同一分钟内重复时该条补秒（HH:MM:SS），不重复不加；跨天每条各带日期。逐条列出是并入机制的对账凭据，价值与用什么标识无关 |
| Q6 | 回退阻断卡 | **时间化 + 水位表补记一列**：水位推进时顺手存「已应用那条保存的写入时刻」（批次终态本就带右端时刻，近零成本；需一次存储迁移）。卡片：`文件里最新的保存（07-01 10:00）早于已应用的保存（08-05 18:24）`。阻断分支补读文件端时刻（现在能读而没读）。旧行无存量时刻 → 降级 `早于已应用水位（应用时刻无记录）`，缺席不摆假数据。**不用挂钟 `applied_at` 兜底**——回退本来就是时间倒挂场景，两把尺子混用最误导 |
| Q7 | 待重试单元来源 | **`来源保存 08-05 18:24`**：`model_update_pending` 表补来源保存时刻列（与 Q6 同批迁移），批次终态落待重试行时写入；旧行缺席则来源段整个不摆 |
| Q8 | 水位的界面指代 | **`水位推进至 08-07 14:33`**，时刻作显示代理。与右端时刻重复是刻意的：partial 行里只有这段在说「数据侧已全部写入、水位已推进、不会重扫」 |
| Q9 | 交付边界 | **设计层先行**：本轮完成画板 + 字段映射 + 术语表 + 本 ADR；验收后再动 gen-model 契约 / 迁移与 plant-ui 代码 |

## 契约与存储新增清单（全部指向本 ADR）

| 位置 | 新增 | 消费者 |
|---|---|---|
| 预览 `DbnumPreview` | **第一条待应用保存的时刻**（Q3 左端；右端复用 `file_latest_sesno_time`） | 确认页批次行 / 未勾选行的窗口时间对 |
| 队列行 `TaskEntry` | `start_sesno_time` / `end_sesno_time`（排队中被并入推高右端时，服务端同步刷新右端时刻） | 队列「保存窗口」列 |
| 批次结果 `DataBatchResult` | `start_sesno_time` / `end_sesno_time` + **merged 逐条时刻**（与 `merged_sesnos` 一一对应） | 终态明细窗口时间对、并入逐条列出、水位落点 |
| 水位表（`dbnum_state`） | **已应用保存的写入时刻**一列（推进时写入；迁移，旧行 NULL） | 回退阻断卡的「已应用」端 |
| `model_update_pending` | **来源保存时刻**一列（终态落行时写入；迁移，旧行 NULL） | 待重试卡「来源保存 …」 |
| 回退异常 `FileAnomaly::Rollback` | 两端时刻（文件端现读补上；已应用端取水位表存量） | 阻断卡 / 队列贴底行 / 日志 |
| 服务端文案 | `DataBatchResult.message` 等提及「会话 N」的句子改说保存时刻 | 终态明细说明位 |

**明确不做**：`SessionPreview` 不加逐会话时刻（Q5 的逐条时刻挂在 `DataBatchResult` 上，
预览侧暂无消费者，等有再进契约——与 ADR-020 的口径一致）。

> **落地校正（2026-08-10，查证 gen-model 源码后）：上表说的「迁移」不存在。**
> `dbnum_watermark` 与 `model_update_pending` 都是 SurrealDB `SCHEMALESS` 表
> （`dbnum_state.rs` 的 `INCREMENT_STATE_SCHEMA`），加字段不需要 DDL 也没有迁移脚本——
> 写的时候多写一个字段、读的时候用 `Option` 接、缺席时走本文的降级规则，就是全部工作。
> 「旧行 NULL」自然成立。**但水位那一列有个坑**：推进语句是
> `applied_sesno = math::max([applied_sesno?:0, end])`（刻意单调），时刻若无条件写，
> 一个 `end_sesno` 偏低的批次会让序号不动、时刻却退回去，而回退卡正好靠这一对。
> 时刻必须跟着同一个条件写。
>

## 降级规则（缺席不摆假数据）

- 老服务端没有时间字段：只报 `N 次保存待应用`，不露 sesno，不摆假时刻，窗口列留空。
- 回退卡已应用端无存量时刻（旧数据）：`文件里最新的保存（07-01 10:00）早于已应用水位（应用时刻无记录）`。
- 待重试行无来源时刻（旧数据）：来源段整个不摆。

## Considered Options

- **回退卡**：时间化 + 补列（采纳）vs 保留 sesno 数字作诊断证据 vs 挂钟 `applied_at` 兜底。
  保留数字给整条流留一个 sesno 敞口；挂钟兜底在时间倒挂场景里两把尺子混用最容易骗人。
- **并入列出**：逐条列时刻（采纳）vs 只报条数 + 最新时刻。后者要改「结果摘要必须逐条列出」
  这条契约，且丢每条保存的可追溯性。
- **水位段**：`水位推进至 <时刻>`（采纳）vs 定性「已追平」vs 删除。partial 行里这段承重，
  重复一次右端时刻换不可误读，值得。
