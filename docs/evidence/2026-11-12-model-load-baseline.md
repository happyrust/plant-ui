## 1. 怎么量

- **节点**（审核第 4 节的四个）：小 ZONE `24383_91690`（7999，137 件）、大 ZONE `17496_8516`（1112，1,888 件）、
  整 SITE `24383_80211`（7999，19 个 ZONE、7,400 件）、大 SITE `23717_2`（7333，531 个 ZONE、79,409 件）。
- **口径**：冷态（每次重开客户端进程，后端不重启）；每档三次取中位数；改动前后**交替**量；release 构建
  （`cargo build -p rs-plant --release --locked`）；记 CPU 占用与有没有 `rustc` 在跑——开始或结束时有编译、或开始时
  CPU ≥ 85% 的标「被搅」单列。基线用 T0 那一笔提交的构建（`git checkout <T0 提交>`），T1 / T2 用期 1 收尾那一笔。
- **客户端侧**：环境变量 `PLANT_UI_LOAD_TIMING=1` 起客户端，接线上后端 8022（只读），点眼睛；网格落定后日志面板与
  stderr 各一行：`装载计时：N 个目标 · 记录首页 +a ms · 记录末页 +b ms（n 发 / k KB / m 条） · 首批实体 +c ms · 网格落定 +d ms · 期间最长一帧 e ms（f 帧）`。
  表里：点击→出图 = `首批实体`；点击→画完 = `网格落定`；记录请求数 = `n 发`；最长一帧 = `e`；进程内存取任务管理器里
  落定那一刻的工作集。整根取法没有逐页进度，`记录首页` = `记录末页`。
- **接口层下限**：`node scripts/model-load-replay.mjs --backend=<8022 的地址> --project=<项目> --mdb=<MDB> --namespace=<ns> --refno=<节点> --repeat=3`，
  三种取法（整根翻页 / 按 ZONE 6 路 / 批量形）各三次报中位数、请求数、字节数。只发只读请求。
- **后端侧**：`model/records` 的 `Server-Timing`（`read` / `total` / `conn`）由脚本累加；后端收到的 `dbnums/*/model/roots`
  请求数看后端访问日志（期 3 的硬指标，这里先记基线）。
