### 过程中暴露并修复的缺陷

- **sRGB 双重编码**：sglDx11 在字节域里算颜色、直写 UNORM 目标；离屏图是 `Bgra8UnormSrgb`，输出前不转线性的话 lightgrey
  画成 130 而不是 189。spike 模式 0 与阶段一探针都钉 189 / 130。
- **透明底交给 egui 混**：vendor 的 bevy_egui 在线性空间里混、还对 Bevy 图再乘一次 alpha，画在背景像素上的边线与邻近亮度之比
  0.63–0.66，画在几何上的是 0.28（E3D 字节域应为 0.26）。改为合成在字节域里画背景、输出不透明。
- **ND 差分侧只比深度差**：深度连续的凸 / 凹棱两侧都跨棱取样，盒子竖棱 61 行缺 10 行、斜棱 57 行缺 6 行；改为按外推误差选侧。
- **WebGL2 读不了深度纹理**：naga GLSL 后端对 `texture_depth_2d` 的 `textureLoad` 直接 panic（wasm spike 模式 4 / 5）。
  改为 prepass 把线性深度拆成 3×10 bit 写进法线纹理 RGB，两端一套着色器。
- **浏览器端首帧的超大渲染目标**：egui 在 bevy_egui 算好相机前按 10000×10000 布局，绘制层要了 6154×6839（超采样 12308×13678）
  的渲染目标，ANGLE 报 “Texture total allocation size is too large” 然后丢上下文。宿主按「视口不可能比窗口大」挡掉。
  （试过在 egui 层看 `raw.screen_rect`，没用：egui 自己会在缩放变化时把这格填上。）
- **离屏图带一整块零字节**：Bevy 启动时上传，WebGL2 不收 BGRA 的 `texSubImage2D`（`invalid format`）；改为 `data: None`。
- **后处理管线无条件排队**：`SglLookPipelines::from_world` 原来不看能力就把七条管线排进 `PipelineCache`，没有半浮点颜色附件的设备上 ND 那条创建即 panic；
  改为先问能力，不支持一条不排、节点不跑。
- **Bevy 色调映射管线对非 HDR 视图也排**：vendor `bevy_core_pipeline` 的 `prepare_view_tonemapping_pipelines` 给每个视图都按 Rgba16Float 排一条
  `tonemapping pipeline`，缺 `EXT_color_buffer_float` 的 WebGL2 设备上应用起不来（与 E3D 外观无关，改动之前就如此）；vendor 本地补丁：非 HDR 视图跳过（见 §5）。
- **设置窗被「渲染外观」一节撑高**：窗是定高的，多出来的内容把「资产 / 服务」几行顶到底栏下面，「供数模式」与「保存」重叠点不到（浏览器里先撕破）；
  内容进 `ScrollArea`，底栏照旧钉在底下。
- **ND 深度存 f16**（2026-10-25 上午查清，§4.4）：ND 纹理是 `Rgba16Float`，a 通道那份线性深度只有 11 bit 尾数，百米外（> 1024 单位）量化步长 ≥ 1 单位 = 100 mm，
  超过 50 mm 的边线深度阈值：平滑面上每跨一个量化台阶，HLR 判据③（c−prev = 0、c−next = ±q → |dot| ≈ h/q）就打一条边，筒体上是等深度线的条纹、穹顶上是同心环，
  再与 2×2 子像素格 / 去杂窗口拍成莫尔纹。来源是 `_ndType = canFloat ? FloatType : HalfFloatType`，移植时只论了 f16 的范围没论精度。
  改为能当颜色附件就用 `Rgba32Float`（`nd_texture_format`），只有半浮点附件的设备才退 f16。
- **Bevy 间接绘制在本机 Vulkan 上 prepass 不落笔**（2026-10-25 下午查清，§4.4 末尾；不是这次改动引入，上游 bevy#18904 / #19000 同类）：`GpuPreprocessingMode::Culling`
  下主通道画得出、prepass 相位整段不落笔，边线 / 伪阴影全无；`NoIndirectDrawing` 或 DX12 即好。加了 `PLANT_UI_INDIRECT_DRAW=0` 逃生口，缺省不开（整库全视直接 draw 24–26 fps，同场景 DX12 间接 32–34 fps）。

### 4.3 整库 7997，Web（2026-10-25 凌晨，headless Chrome / ANGLE D3D11 / RX 590，release wasm + `look-demo`，库供数）

### 4.4 远景条纹 / 同心环：根因与修法（2026-10-25 上午，headless Chrome / ANGLE D3D11 / RX 590，release wasm + `look-demo`）

**根因**：ND 纹理是 `Rgba16Float`，a 通道里的线性深度就是 HLR / HBAO / 模糊比对的那份。f16 只有 11 bit 尾数：1024–2048 单位（102–205 m）步长 1 单位 = 100 mm，
再远一倍就是 200 mm，都超过 50 mm 的边线深度阈值。平滑面上每跨一个量化台阶，判据③的两个梯度向量一个竖直一个近乎水平（c−prev = 0、c−next = ±q），|dot| ≈ h/q ≪ 0.9999 → 边。
筒体上这些边是等深度线（从上往下看是一圈圈箳），穹顶上是同心环；台阶间距与 2×2 子像素格 / 去杂窗口拍成莫尔纹，所以是「四瓣」。
两端差异不是平台差异：PC 那张全视里每个 ND 像素都跨台阶，去杂把满屏的边均成了一层均匀压暗；Web DPR 2 下台阶间距 2–3 个 ND 像素，正好过去杂又拍得出条纹。
来源 `sglLookPipeline.ts` 本来就是 `_ndType = canFloat ? FloatType : HalfFloatType`；计划书里写 `Rgba16Float` 时只论了范围（65504 单位够）没论精度。

**修法**：`nd_texture_format(adapter)`——`Rgba32Float` 能当颜色附件就用它（原生恒可；WebGL2 的 `EXT_color_buffer_float` 两种都给），只有 `EXT_color_buffer_half_float` 的设备才退 `Rgba16Float`（百米外照旧会出条纹，同来源）；
纹理与 ND 管线的目标格式都从 `SglLookPipelines::nd_format` 取。配套加了两件查案工具：
- `--look-debug=<模式>` / `?look_debug=<模式>`（`SglLookDebugView`，任何构建都带）：合成段把 `depth`（prepass 线性深度，1 m 锯齿）/ `depth_error`（ND 深度相对 prepass 30 bit 深度的误差，按边线阈值归一，绿 0 → 红 ≥ 1 个阈值）/ `normal` / `flags` / `edges`（去杂前 HLR）/ `ao` 直出到视口；
- `--look-demo=far` / `?look_demo=far`：演示厂北面 250 m 外多摆一件 Ø 60 m × 70 m 筒体 + Ø 60 m 穹顶（安全壳尺寸），只框它取景（相机约 180 m，近面 150 m、远面 210 m），不要模型库也能复现 / 复查。

**A/B（同一浏览器、同一场景、同一视角，只换 ND 格式；临时把 `nd_format_for` 强成 f16 重编了一次 wasm，验完恢复）**，截图在 `far/`（视口裁切，968×512 CSS px，DPR 1，SSAA 离屏图 1942×1048）：

**PC 端这次是在 DX12 上复验的，因为本机的 Vulkan 路今天不出 prepass（下午查清是 Bevy 间接绘制的机器相关缺陷，见本节末尾）**：HEAD（9389b9177）的 release 构建，不论带不带这次改动，演示厂在缺省的 Vulkan 后端上都**没有边线 / 伪阴影**（`far/pc-demo-head-no-edges.png`，对照昨天的 `phase2/app-look-demo-e3d-factory-hlr-ao.png`）。
运行时诊断（临时打点，已撤）：7 个 `SglLookMaterial` 实体、不透明、标记 3、可见；相机 `NormalPrepass` 在、`Msaa::Off`；prepass 法线纹理 2952×1778 `Rgb10a2Unorm` 存在；`Opaque3dPrepass` 相位有 1 个批；
视图键 `MeshPipelineKey(NORMAL_PREPASS)`；可是就算 prepass 片元里写常数，合成段读到的法线纹理仍全零——prepass 的 draw 在 GPU 上没落笔。
二分（主工作树里切提交构建）：23a9c2d92（虚拟孔洞）一样；**b05fc67b6（外观提交本身）也一样**，debug / release 都一样，把 vendor 的色调映射补丁摘掉重编还是一样——而昨晚 23:45 同一份代码的 AMS 截图（§6）边线都在。
同一个二进制换 `WGPU_BACKEND=dx12`：边线 / 伪阴影照常（`far/pc-demo-head-dx12.png`）。所以不是代码回归。

**下午查到位（关掉另外两个 plant-ui 实例、把 AMD `VkCache` 换成空的都没用之后）**：症结在 **Bevy 0.16 的 GPU 驱动间接绘制**（`GpuPreprocessingMode::Culling`：预处理计算着色器填 indirect 参数 + `multi_draw_indirect_count`）。
同一个 release 二进制、同一演示厂、Vulkan，只改预处理档位（临时在 `RenderApp` 里压 `GpuPreprocessingSupport`，启动时打印确认，验完撒），探针截图同一块视口裁切数暗像素：

| 后端 | 预处理档位 | 边线 / 伪阴影 | 暗像素数（亮度 < 110 / < 140） |
|---|---|---|---|
| Vulkan | `Culling`（缺省，间接绘制） | **无**（`vulkan/pc-demo-vulkan-indirect.png`） | 31 / 144 |
| Vulkan | `PreprocessingOnly`（变换在 GPU 算，直接 draw） | 有（`vulkan/pc-demo-vulkan-direct.png`） | 195 / 662 |
| Vulkan | `None`（CPU 预处理） | 有 | 195 / 662 |
| DX12 | `Culling` | 有（`vulkan/pc-demo-dx12.png`，与上一行逐字节相同） | 195 / 662 |

主通道走间接路径画得出来、prepass 相位走同一条路径却整段不落笔，只在 Vulkan（RX 590 / AMD proprietary 26.1.1）上——与上游 bevy#18904 / #19000 记的「Vulkan + 间接绘制在某些驱动上整件消失 / 乱画，挂 `NoIndirectDrawing` 即好、换 DX12 即好」是同一类机器相关缺陷（上游 0.17.1 仍开着）。
昨晚能出、今天不出：这类缺陷在上游报告里也是时隐时现；本机排过的环境项（驱动 / PnP / Vulkan 层与 ICD / 显示配置 / 事件日志里的 TDR）都没变。
上午「去掉 `MULTI_DRAW_INDIRECT` 特性没有改变」那条与此矛盾，那次没有打印实际生效的档位，以下午这组（档位已打印确认）为准。
`WGPU_SETTINGS_PRIO=compatibility` / `webgl2` 都试不了（Bevy 的遮挡剔除 / 大气 LUT 计算管线在那些限制下建绑定组布局就 panic）。

**处置**：`plant-ui-view3d` 加了逃生口 `PLANT_UI_INDIRECT_DRAW=0`（主相机挂 Bevy 的 `NoIndirectDrawing`，这个视图退到 `PreprocessingOnly`）；启动时 `[渲染]` 一行说明适配器 / 后端 / 开关。
**缺省仍开间接绘制**，因为真模型上代价不小——同一天同一套做法（库供数，10 个 SITE，约 5.0 万网格实体，装完后按 fit 全视，每档采 20 s）：

| Vulkan，整库全视 | 帧时间 | GPU 3D 引擎占用 | 进程 CPU |
|---|---|---|---|
| 间接绘制（缺省；今天 prepass 没落笔，`vulkan/pc-library-vulkan-indirect.png` 无边线） | 16.7 ms（顶在垂直同步 60 fps） | 66 % | 1.1 核 |
| `PLANT_UI_INDIRECT_DRAW=0`（直接 draw；边线 / 伪阴影回来，`vulkan/pc-library-vulkan-direct.png`） | **39–41 ms（24–26 fps）** | 37 % | 1.1 核 |
| `WGPU_BACKEND=dx12` + 间接绘制（prepass 正常，同一场景 50 261 实体，`vulkan/pc-library-dx12-indirect.png`；当晚补量） | **30–31 ms（32–34 fps）** | 49 % | 1.05 核 |

读法：Vulkan 间接那行的 16.7 ms 是没画 prepass 的数，不能当基准；公平的对照是同场景的 DX12 间接绘制——直接 draw 比它慢约三成（40 vs 30 ms），比§4.2 间接路径正常那天的 Vulkan（17.5–21 ms，12 个 SITE）慢一倍。
直接 draw 下 GPU 闲着六成：5 万实体 × prepass + 主通道两遍的提交端在卡，正好压在计划「整库 ≥ 24 fps」的门槛上。
所以本机想要边线又不想掉帧，眼下更好的办法是 `WGPU_BACKEND=dx12`（间接路径在 DX12 上是好的）；`PLANT_UI_INDIRECT_DRAW=0` 留给没有 DX12 的机器。用户 2026-10-25 拍板：Windows 上缺省不改（Vulkan + 间接绘制），逃生口留着。

**真模型复验**：整库 7997 在浏览器里用修后的 wasm 重跑了一次（§4.3，`ams/web-library-7997-e3d-f32-{fit,dome}.png`，对照修前的 `ams/web-library-7997-e3d-far-rings.png`）：条纹 / 同心环没有了。
FXAA 对照当晚补量了，见 §4.3。

## 5. 降级路径（2026-10-24 走过）

实现：`RenderAdapter::get_texture_format_features(Rgba16Float)` 不含 `RENDER_ATTACHMENT` → 不挂 prepass / 后处理 / 超采样，留 MSAA，
设置窗「边线 / 伪阴影」两格灰掉并说原因，日志一行；单元测试钉了灰显与 `render_scale` 回 1。wgpu 在 WebGL2 上是按 `EXT_color_buffer_float`
判半浮点可渲染的（它找的 `GL_EXT_color_buffer_half_float` 带 `GL_` 前缀，WebGL 从不这么报），文案里的扩展名按这个改了。

模拟缺扩展用了两种方式，抓到两处启动即崩、都修了：

1. **藏扩展**（最接近真机）：index.html 副本里给 `WebGL2RenderingContext.prototype.getSupportedExtensions / getExtension` 打补丁，把
   `EXT_color_buffer_float` / `EXT_color_buffer_half_float` 藏起来，release wasm（`look-demo`）走 `?look_demo=1`。
   - 第一跑：探测命中、日志一行打出来，然后 **panic** 在我们自己的 `sgl look nd` 管线（`PipelineCache` 排了就编，“Format Rgba16Float is not renderable”）。
     **修**：`SglLookPipelines::from_world` 先问能力，不支持就一条管线都不排，节点不跑。
   - 第二跑：panic 换成了 Bevy 自己的 `tonemapping pipeline`——vendor 的 bevy_core_pipeline `prepare_view_tonemapping_pipelines` 给**每个**视图都按
     `ViewTarget::TEXTURE_FORMAT_HDR`（Rgba16Float）排一条管线，不管相机是不是 HDR；也就是真缺这个扩展的设备上 Bevy 0.16 本身就起不来，与 E3D 外观无关、改动之前就如此。
     **修**（vendor 本地补丁）：`vendor/registry/bevy_core_pipeline/src/tonemapping/mod.rs` 里非 HDR 视图直接 `continue`（`TonemappingNode` 对非 HDR 视图本来就跳过，
     这条管线排了也没人用），`.cargo-checksum.json` 同步；补丁头上写明来历，按 fork 仓路径写的 `git am` 补丁在 `vendor/patches/`（在干净的上游文件上 `git am` 试过，重新 vendor 前先推到 happydpc/bevy）。cargo 不跟踪 vendor 源码改动，
     改完要 `cargo clean -p bevy_core_pipeline`（每个 target / profile 各一次）才会重编。
   - 第三跑（截图 `phase4/web-degraded-hidden-extensions-{view,settings}.png`）：**不崩**。控制台依次是
     `[degrade-sim] hidden WebGL2 extensions: EXT_color_buffer_float, EXT_color_buffer_half_float` →
     `[E3D 外观] 这台设备没有半浮点颜色附件（WebGL2 缺 EXT_color_buffer_float），边线 / 伪阴影关闭，材质与背景照常` →
     `[look-demo] 平均帧时间 16.68 ms（60 fps），离屏图 1463×767（逻辑 1463×767 × 1）…`；没有 `panicked`、没有 GL 错误。视口是 E3D 材质 + egui 那层背景渐变，
     没有边线 / 伪阴影；设置窗「边线 / 伪阴影」两格灰掉、悬停说原因，背景渐变 / 抗锯齿照常可改。演示厂那行帧时间日志末尾现在会注明
     「设置值；这台设备没有半浮点颜色附件，边线 / 伪阴影 / 超采样都没生效」，不再把没有的东西说成有。
2. **强制探测为否**（临时改一行重编 wasm，验完恢复；截图 `phase4/web-degraded-no-float-targets-{view,settings,log}.png`）：扩展都在、只是我们这边当作没有。
   结果与上面第三跑一致：不崩；日志一行；离屏图 1463×767 × 1（设置仍是 SSAA 2×2 但 `render_scale` 回 1），60 fps；首次启动那句日志改为
   「边线 / 伪阴影 / 超采样在这台设备上不可用」。

没做：真缺扩展的物理机器（手头没有）；两种模拟都是 Chrome ANGLE D3D11 上藏 / 忽略扩展。
